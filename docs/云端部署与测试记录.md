# 云端部署与测试记录

## 目标与产品决策（2026-10-13）

用户要求公网可访问，任何人能看已订阅 UP 主与分析，只有本人可以管理、搜索新 UP 主或触发采集/AI；随后明确采集、AI 和数据库全部迁云。已有 GitHub、Vercel 账号。云端使用 **DeepSeek 官方 API**，先由用户手动测试，再开启自动任务。

验收分三层：连接可用；单条观点有原文引用且能切换作者；云端采集与定时链路稳定。免费托管额度与模型 API 费用分别核算。

## 已有公网展示

- [只读展示](https://georgehuang000.github.io/bili-finance-public/)，GitHub Pages 托管。
- 2026-10-13 快照含 7 位作者、23 篇总结、270 条观点，约 1MB。
- 树莓派 `bili-public-sync.timer` 每15分钟仅发布脱敏 JSON 与前端文件，专用 deploy key 仅有展示仓库权限。
- 前端只读适配器拒绝管理、搜索和模型请求；线上验证搜索/设置无接口，写入拒绝。
- 此版本依赖树莓派发布，不代表全云迁移完成；迁移验证前继续保留。

## 调研与方案选择

- [Vercel FastAPI](https://vercel.com/docs/frameworks/backend/fastapi)：复用现有 Python 后端，无需重写为 Node。
- [函数时长](https://vercel.com/docs/functions/configuring-functions/duration)：Hobby 上限300秒，长采集/模型任务不能靠请求结束后的线程维持。
- [Neon 原生集成](https://vercel.com/marketplace/neon)：从 Vercel 创建 Neon 账号，套餐起价0美元，无需先独立注册；开通时核对实际免费选项。
- [Neon 免费额度更新](https://neon.com/blog/neon-free-plan-1-gb-per-project)：2026-10-02 起每项目1GB、100 CU小时/月。现有 SQLite 备份约2.7MB。
- [GitHub Actions 计费](https://docs.github.com/en/billing/concepts/product-billing/github-actions)：公开仓库的标准托管 runner 免费；仅仓库自己的默认分支执行凭据任务，不使用 fork PR。
- [SQLite 限制](https://vercel.com/kb/guide/is-sqlite-supported-in-vercel)：Vercel 本地文件不能当持久数据库。
- 2026-10-13 查询 GitHub 官方 API：FastAPI 103,066 stars、SQLAlchemy 12,229 stars、Celery 28,964 stars。Celery 成熟但需额外 broker/常驻 worker；本项目低并发，先复用 SQLAlchemy/Postgres 队列与 GitHub runner，减少服务数量。
- Render 免费实例休眠且本地文件临时、免费 Postgres 有时限；Koyeb 免费规格低且不支持持久卷。未选择为本次主路径。

## 实现流程

1. 保留 SQLite 默认模式，新增 `DATABASE_URL` PostgreSQL 模式；视频/动态 UPSERT 按数据库方言处理。
2. 财务分析表保留既有 SQL 合约，使用 SQLAlchemy 绑定参数与事务；Postgres 插入用 RETURNING 获取 ID，原文引用与历史 ID 保持可追溯。
3. Vercel 使用根目录 `app.py` 入口与 React 构建；云端禁用 APScheduler 与采集后后台分析线程。
4. 后端只读路由白名单；搜索、订阅变更、扫码、模型设置/测试、采集和核验均需要管理员会话。未订阅作者的内容接口返回404。
5. 管理密码使用 scrypt 哈希，会话随机令牌仅存摘要；Cookie 使用 Secure/HttpOnly/SameSite=Strict。登录次数限制存在数据库，跨冷启动有效。
6. 模型 Key 与 B站 Cookie 用独立 Fernet 密钥加密保存，网页不返回原文。云端只允许 DeepSeek 官方地址。
7. 长任务落库，runner 领取并记录完成/失败；GitHub 并发组串行运行。初始 `CLOUD_TEST_MODE=true`、定时采集关闭，单次观点分析最多一条素材且必须选择作者。
8. `tools/migrate_cloud_data.py` 只读 SQLite 备份，要求目标内容表为空，整批事务校验行数并重置序列，不复制凭据、不覆盖已有目标。

- 本机隔离 Docker PostgreSQL16，数据库名 `bili_cloud_test`；首选15432端口被占用，改用随机本地端口，未操作其他项目容器。
- 原有11项分析测试通过；9项真实PostgreSQL集成测试通过，覆盖匿名管理拒绝、作者范围、会话注销/来源、持久限流、密钥加密、官方API地址约束、UPSERT保留正文、引用与事务、并发任务去重。
- React 生产构建通过。未在单元/集成测试中调用真实模型或 B站。
- 从树莓派创建一致性只读备份，迁入本地隔离 PostgreSQL 后逐字段比对10张内容表：8条作者记录（含1位已取消订阅）、881条视频、473条动态、23篇总结、160条分析素材、477条历史观点、5条重试记录、79条分析运行记录。全部字段一致，源数据未修改；此为迁移演练，尚未写入 Neon。
- 浏览器验证公开访客只有管理登录入口，可以切换作者；登录后显示“测试一条素材”，退出后所有管理控件隐藏。未点击真实收费任务。
- 文本连通测试输出上限256 tokens，界面显示输入/输出tokens；云端测试分析输出上限6000 tokens并关闭自动重试，初始图片识别关闭。

## 测试部署步骤

1. Vercel 新项目部署代码，保持 `CLOUD_TEST_MODE=true`。未连接数据库时后端返回503，不创建临时业务数据库。
2. 在项目 Storage 添加 Neon，选择免费套餐并连接项目，让 Vercel 注入 `DATABASE_URL`。
3. 配置 `ADMIN_PASSWORD_HASH` 与 `CREDENTIAL_ENCRYPTION_KEY` 为加密环境变量；GitHub secrets 保存同一 `DATABASE_URL` 与加密密钥。
4. 从树莓派生成一致性 SQLite 备份，导入空的测试数据库，核对每表行数和引用。
5. 管理登录后在“模型设置”保存 DeepSeek 官方 Key，先点“测试连接”；选择一个 UP 主再点“测试一条素材”。GitHub Actions 手动运行 worker，查看任务结果。
6. 用户确认效果后才开 `CLOUD_ENABLED=true`（队列轮询）、`CLOUD_TEST_MODE=false` 与定时采集变量；需在云端实测 B站登录/风控，再切换树莓派任务。

## 难点与未完成项

- Vercel 函数重启频繁，不能把内存锁、文件状态、后台线程当持久任务系统；已改为数据库状态与 runner。
- 数据中心出口可能触发 B站风控，不能以本地采集成功代替云端实测。
- GitHub cron 可能延迟，按钮准确提示排队，不承诺立即执行。
- Neon 资源尚需开通并连接；数据库迁移、真实云端模型调用与采集验证尚未完成。完成前不停止树莓派，不开启全量自动收费任务。
- 云端源代码已发布到[独立测试仓库](https://github.com/georgehuang000/bili-finance-cloud)，未提交任何数据库、Cookie或Key。Vercel连接可读取账号信息，但创建项目在其项目空间返回403；用户已表示将手动导入仓库并连接Neon，目前不宣称部署成功。
- DeepSeek 官方[模型文档](https://api-docs.deepseek.com/quick_start/pricing/)当前推荐 `deepseek-flash`，测试默认关闭思考；API实际调用独立计费。
