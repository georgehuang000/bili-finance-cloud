# 云端部署与测试记录

## 目标与产品决策（2026-10-13）

用户要求公网可访问，任何人能看已订阅 UP 主与分析，只有本人可以管理、搜索新 UP 主或触发采集/AI；随后明确采集、AI 和数据库全部迁云。已有 GitHub、Vercel 账号。云端使用 **DeepSeek 官方 API**，先由用户手动测试，再开启自动任务。

验收分三层：连接可用；单条观点有原文引用且能切换作者；云端采集与定时链路稳定。免费托管额度与模型 API 费用分别核算。

- 2026-10-13 快照含 7 位作者、23 篇总结、270 条观点，约 1MB。

## 调研与方案选择

- [Vercel FastAPI](https://vercel.com/docs/frameworks/backend/fastapi)：复用现有 Python 后端，无需重写为 Node。
- [函数时长](https://vercel.com/docs/functions/configuring-functions/duration)：Hobby 上限300秒，长采集/模型任务不能靠请求结束后的线程维持。
- [Neon 原生集成](https://vercel.com/marketplace/neon)：从 Vercel 创建 Neon 账号，套餐起价0美元，无需先独立注册；开通时核对实际免费选项。
- [Neon 免费额度更新](https://neon.com/blog/neon-free-plan-1-gb-per-project)：2026-10-02 起每项目1GB、100 CU小时/月。现有 SQLite 备份约2.7MB。
- [GitHub Actions 计费](https://docs.github.com/en/billing/concepts/product-billing/github-actions)：公开仓库的标准托管 runner 免费；仅仓库自己的默认分支执行凭据任务，不使用 fork PR。
- [SQLite 限制](https://vercel.com/kb/guide/is-sqlite-supported-in-vercel)：Vercel 本地文件不能当持久数据库。
- 2026-10-13 查询 GitHub 官方 API：FastAPI 103,066 stars、SQLAlchemy 12,229 stars、Celery 28,964 stars。Celery 成熟但需额外 broker/常驻 worker；本项目低并发，先复用 SQLAlchemy/Postgres 队列与 GitHub runner，减少服务数量。
- Render 免费实例休眠且本地文件临时、免费 Postgres 有时限；Koyeb 免费规格低且不支持持久卷。未选择为本次主路径。

## 实现流程

1. 保留 SQLite 默认模式，新增 `DATABASE_URL` PostgreSQL 模式；视频/动态 UPSERT 按数据库方言处理。
2. 财务分析表保留既有 SQL 合约，使用 SQLAlchemy 绑定参数与事务；Postgres 插入用 RETURNING 获取 ID，原文引用与历史 ID 保持可追溯。
3. Vercel 拟部署 `server`/`web` 两个服务，后端入口 `vercel_entry:app`；根目录 `app.py` 为兼容入口，云端禁用 APScheduler 与采集后后台分析线程。
4. 后端只读路由白名单；搜索、订阅变更、扫码、模型连接测试、采集和核验均需要管理员会话。未订阅作者的内容接口返回404。
5. 管理密码使用 scrypt 哈希，会话随机令牌仅存摘要；管理会话 Cookie 使用 `__Host-` 前缀、Secure/HttpOnly/SameSite=Strict，8小时有效。登录次数限制存在数据库，跨冷启动有效。
6. 模型 Key 只从部署环境读取，网站不提供修改接口或表单，不写入业务数据库。B站 Cookie 用独立 Fernet 密钥加密保存，网页不返回原文；云端只允许 DeepSeek 官方地址。
7. 长任务落库，runner 领取并记录完成/失败；GitHub 并发组串行运行。初始 `CLOUD_TEST_MODE=true`、定时采集关闭，单次观点分析最多一条素材且必须选择作者。
8. `tools/migrate_cloud_data.py` 只读 SQLite 备份，要求目标内容表为空，整批事务校验行数并重置序列，不复制凭据、不覆盖已有目标。

## 测试部署步骤

1. 用户确认服务配置后推送候选代码；在 Vercel 导入项目，保持 `CLOUD_TEST_MODE=true`。未连接或初始化数据库时后端返回503，不创建临时业务数据库。
2. 在项目 Storage 添加 Neon，选择免费套餐，建立本应用专用数据库。Preview 使用独立测试数据库与凭据，不复用 Production 的 B站登录态或模型 Key。
3. 在本机私有环境加载迁移用的数据库 owner 连接，运行 `tools/migrate_cloud_data.py` 导入一致性 SQLite 备份，逐字段核对。函数和worker启动时不执行建表；升级表结构也由迁移账号执行。
4. 用迁移账号运行 `tools/provision_cloud_roles.py`，创建受限网页/worker角色。两个连接串只写入受保护的本机文件：Vercel 的 `DATABASE_URL` 使用 `api-database.env`，GitHub Actions 的 `DATABASE_URL` 使用 `worker-database.env`。运行环境不使用迁移账号。
5. Vercel Production 添加 Secret 类型的 `ADMIN_PASSWORD_HASH`、`CREDENTIAL_ENCRYPTION_KEY`、`DEEPSEEK_API_KEY` 和受限 `DATABASE_URL`。GitHub Actions secrets 添加 worker连接串、同一 Cookie 加密密钥和 DeepSeek Key；不上传 `.env`、数据库备份或明文 Cookie。
6. 管理登录后先点“测试模型连接”，只使用服务器既有配置；扫码保存 B站登录态，选择一个 UP 主，再点“测试一条素材”。GitHub Actions 手动运行 worker，查看结果。网站不能修改模型 Key、模型地址或供应商。
7. 用户确认效果后才开 `CLOUD_ENABLED=true`（队列轮询）、`CLOUD_TEST_MODE=false` 与定时采集变量；需在云端实测 B站登录/风控，再切换树莓派任务。

## Vercel Services 配置修订（2026-10-13）

- 顶层移除 buildCommand/functions，分别放入具体服务；后端服务独立安装 requirements-cloud.txt。
- 硬编码的 Vite localhost 代理已改为可选 `LOCAL_API_URL`；使用 Vercel 联合开发不需要代理。单独运行 Vite 时可设置该开发环境变量。
